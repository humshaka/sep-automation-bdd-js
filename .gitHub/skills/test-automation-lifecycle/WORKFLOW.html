The 4 Specialized BDD Sub-Agents

Each agent has a strictly delineated role, specialized domain prompt, and enforced quality boundary.

🧠

Planner Agent

@planner
Requirements

Deconstructs feature file header comments into discrete acceptance criteria. Enforces the strict 1-to-1 AC-to-Scenario rule, verifies existing steps in CommonSteps.js to eliminate duplicates, and maps catalog data from qa-data-reader.js.

Input: Target feature file with #* AC comments
Output: Scenario outline matrix & POM gap report
Boundary: Zero code generation; pure architectural plan
Config: .github/agents/planner.agent.md Deterministic
🔍

Explorer Agent

@explorer
Playwright MCP

Connects to the live application via @modelcontextprotocol/server-playwright. Inspects the accessibility tree, verifies Angular SPA state reactivity (button enable/disable, stepper highlights), and discovers user-facing semantic locators.

Input: Target UI workflows & element candidate list
Output: Validated getByRole / semantic locators
Boundary: Bans brittle absolute XPaths; validates DOM
Config: .github/agents/explorer.agent.md Live DOM
⚡

Generator Agent

@generator
Code Synthesis

Synthesizes Cucumber step definitions in steps/ and updates Page Objects in pages/. Employs web-first retrying assertions (await expect(...)), strictly forbids hardcoded sleeps, and runs --dry-run preflight verification.

Input: Planned scenarios & verified MCP locators
Output: Completed .feature scenarios & steps/*.js
Boundary: Zero duplicate step definitions; ESM imports
Config: .github/agents/generator.agent.md Dry-Run Gate
🩹

Healer Agent

@healer
Self-Healing

Autonomously triages test failures using Cucumber JSON reports and screenshots. Employs 3-tier classification: patches code if automation-code, alerts SDET if environment data, or files a bug report if product defect.

Input: Stack trace, screenshot, failure step report
Output: Targeted code patch or Defect issue summary
Boundary: Max 3 healing loops; halts on real app defects
Config: .github/agents/healer.agent.md 3-Tier Guard

// ENTERPRISE STANDARDS

The 6-Point Quality Reviewer Gate (`/pr-reviewer`)

Before code is pushed or a PR is opened, local changes are audited against these 6 non-negotiable enterprise quality rules.

1

1:1 AC Coverage

Every header #* AC comment must produce an independent, dedicated scenario tagged @<tag>-1, @<tag>-2. No criteria may be omitted.

2

Locator Resilience

Mandates user-facing semantic locators (getByRole, getByLabel, getByText). Strictly forbids brittle absolute XPaths (/html/body/...).

3

Zero Hardcoded Waits

Relies 100% on Playwright's native auto-waiting and retrying assertions. Strictly bans page.waitForTimeout() and setTimeout().

4

Web-First Assertions

Every Then step must utilize asynchronous retrying assertions: await expect(locator).toBeVisible(). Bans synchronous assertions.

5

Page Object Discipline

Locators and page actions remain encapsulated in pages/*.js. Step definitions import page singletons from globalPagesSetup.js.

6

Security & Secret Hygiene

Credentials must load strictly via process.env from .env. Zero passwords, auth tokens, or private endpoints in repository code.
